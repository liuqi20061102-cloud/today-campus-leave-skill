# 今日校园请假条时间编辑器

根据用户提供的“今日校园”请假条截图和目标请假时间，生成视觉上忠于原图、时间线与请假状态完全自洽的测试素材。

本技能只处理“今日校园”请假条测试截图。收到其他产品截图时，不执行本流程。即使同属“今日校园”，不同学校、版本和页面状态的布局也可能不同，因此必须根据图片中的实际内容智能识别字段，不能套用固定模板。

## 工作流程

### 1. 确认输入属于目标场景

确认用户提供了“今日校园”的请假条截图，并要求修改请假日期或时间。图片可以是请假详情、请假申请、审批结果、待休假、休假中、已结束、续假或销假等页面。

将图片作为用户软件测试素材处理。保留原图中已有的测试标识、调试时间浮层或其他测试环境信息，除非用户明确要求修改。

完成标准：确认图片属于“今日校园”请假条场景，并识别当前页面类型和状态。

### 2. 明确目标时间

根据客户端的当前日期和时区，将“今天”“下周一”等相对日期换算成准确日期，并使用确定性的日期计算核对星期。

提取用户要求的请假开始时间、结束时间以及明确提出的流程要求。统一理解“上午 9.40”为 `09:40`、“下午 3 点 40”为 `15:40` 等自然语言表达。时长必须根据起止时间重新计算，不能照抄原图。

完成标准：目标日期、星期、时间区间、时长和预期截图时刻均已明确。

### 3. 盘点整张图片

编辑前，使用 `view_image` 并以原始清晰度检查源图。识别所有可能约束目标场景的元素，包括用户没有明确提到的内容：

- 状态栏时钟以及页面内嵌的“当前时间”浮层；
- 请假开始时间、结束时间、总时长、实际休假时间，以及“昨天”“今天”“明天”“即将休假”等相对时间表述；
- 申请发起、催办、审批通过、驳回、续假、销假和结束等流程记录及其时间；
- “审批已通过”“即将休假”等横幅、审批印章、状态标签、操作按钮和审批步数；
- 请假类型、是否离校、销假规则、请假原因、发起位置、抄送人和宿舍信息等内容；
- 被遮挡、重复出现或相距较远，但可能残留旧值的字段。

同时记录姓名等身份文字、版式、图标、颜色以及必须保持不变的无关内容。

完成标准：所有可见的时间元素和状态元素都已纳入检查，不能只检查以往案例中出现过的字段。

### 4. 建立请假事件关系图

排列识别到的事件，并验证它们之间的约束。常见的顺序是：

`发起申请 < 发起催办 < 审批通过 <= 截图时刻 < 请假开始 < 请假结束 < 续假或销假`

应根据实际界面调整事件关系。至少检查：

- 各时间戳按照预期顺序递增；
- 显示的时长等于开始与结束时间的准确差值，跨天情况也必须正确；
- 手机顶部时间、页面内“当前时间”浮层和流程记录中的日期、时间互相一致；
- 截图时刻与“待审批”“审批已通过”“即将休假”“休假中”“已结束”“已销假”等页面状态一致；
- 请假开始前，“实际休假时间”应为空；只有已进入或完成休假流程时才能填写；
- 除非产品明确允许中间存在空档，否则续假应从上一段时间的结束时刻开始；
- 流程步数、审批人、印章和操作按钮必须与当前流程状态一致；
- 相对时间表述仍然指向正确的日历日期。

选择一个合理的截图时刻，使尽可能多的现有界面元素可以自然成立，并尽量减少修改范围。只有在多个产品状态同样合理，而且不同选择会实质改变用户要求时，才向用户询问。

完成标准：一个连贯的事件关系图可以解释所有保留字段，并确定所有必须修改的字段。

### 5. 制定编辑方案

确定准确日期、请假区间、时长、截图时刻，以及所有需要联动修改的字段。若用户只给出请假区间，则自行选择合理的申请、催办、审批和截图时间，不因用户没有逐项指定而遗漏这些字段。

使用 `image_gen` 编辑图片。在提示词中：

- 逐项列出需要替换的旧文字和对应的新文字；
- 说明目标事件顺序，以及保留的页面状态为何合理；
- 保持画布尺寸、裁剪范围、字体风格、间距、颜色、图标和无关像素不变；
- 原样保留所有无关文字；
- 要求汉字与数字清晰、完整、对齐；
- 只有事件关系确实要求时，才增加或删除界面区域。

完成标准：提示词覆盖所有受事件关系影响的修改，并明确列出必须保持不变的内容。

### 6. 校验生成结果

绝不能在图片生成后直接交付。必须用 `view_image` 以原始清晰度重新打开生成的图片，再次阅读和检查整张图片。

使用 PowerShell、Python 或其他确定性的本地方法，独立计算日期、星期和时长。检查：

- 图片中已经显示用户要求的请假日期和时间；
- 整张图片中没有残留任何旧时间戳或旧时长；
- 所有事件时间都符合事件关系图；
- 手机状态栏、调试时间浮层、申请记录、催办记录和审批记录之间不存在时间倒置；
- 状态标签、印章、按钮和实际使用字段与截图时刻一致；
- 相对时间表述仍然成立；
- 无关的姓名、原因、位置、数量和标签没有被错误修改；
- 数字和汉字完整、清晰、对齐，并且没有被遮挡；
- 没有任何区域被意外裁剪、移动、复制或删除。

生成调用成功、图片看起来相似或其他间接信号都不能证明结果正确，必须以最终生成图片中的实际像素为准。

完成标准：所有时间元素和状态元素均通过检查，视觉对比也没有发现非预期修改。

### 7. 修正并重新检查

任何检查项失败时，都要继续编辑，并重新执行完整校验。如果只有一个局部问题，应在最新的高质量结果上继续修正；如果多个互不相关的区域都出现劣化，应回到原图，并使用更完整、更严格的提示词重新生成。

持续修正，直到满足完成标准。如果经过合理次数的重试后，图片模型仍无法可靠呈现所需文字，应准确说明仍存在的缺陷，不能声称任务已经成功完成。

### 8. 交付结果

返回最终图片路径，并附上简明的检查记录，包括：

- 准确的请假日期、时间区间和计算后的时长；
- 申请、催办、审批、截图、请假开始和结束的最终事件顺序；
- 页面状态与相对时间检查结果；
- 已检查旧值残留和视觉缺陷；
- 确实存在的剩余限制。

不得将检查失败或尚未验证的生成结果作为最终成品交付。
